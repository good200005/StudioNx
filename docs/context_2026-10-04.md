### 3.3 Git · YouTrack 규칙
| 규칙 | 내용 |
|---|---|
| 브랜치 흐름 | `feature/phase1/p1-NN-*` → PR → `feature/phase1-account` → (Phase 1 끝) `develop` → `main` |
| 구현 브랜치 | Phase 1 작업 브랜치 19개를 `feature/phase1-account`와 같은 커밋으로 맞춰 둠. **시작 전 `git merge feature/phase1-account`** 로 앞 단계 구현 받기 |
| PR 병합 후 | 해당 YouTrack 이슈 Closed + 다음 작업 요약 (`CLAUDE.md`). **템플릿만 병합된 작업은 In Progress** |
| 여러 PR을 이어 만들 때 | 같은 파일을 고치면 앞 브랜치에서 이어 만들고 순서대로 병합. 병합 후 브랜치 자동 삭제가 꺼져 있어 다음 PR의 대상을 `feature/phase1-account`로 바꿔야 함 |
| 병합한 브랜치 | 사용자가 요청하면 로컬·원격 삭제 |

### 3.4 결정 사항
| 결정 | 내용 |
|---|---|
| 로그인 | 별도 페이지 없음 → `home.html` 로그인 모달. 로그인이 필요한 페이지는 `home.html#login?next=<원래 페이지>` |
| 토큰 | Access 30분(메모리) + Refresh HttpOnly 쿠키 `snx_refresh` (자동 로그인 체크 3일, 아니면 세션 쿠키). DB에 저장하지 않음 |
| 비밀번호 규칙 | 8~20자, 대·소문자·숫자·키보드 기호 각 1개 이상, 한글·공백 불가 (화면 `join.js` = 서버 `check_password_rules`) |
| 탈퇴 | 소프트 삭제. 같은 이메일·닉네임은 **3일 뒤** 재가입 (`REJOIN_TOO_SOON`, `release_withdrawn`). 탈퇴자의 OWNER 프로젝트는 **남김** (PRD 01 FR-108) |
| 문의 제한 | 같은 IP·이메일 10분에 3번, **서버 메모리** 방식 (FR-113) |
| 프로필 사진 | `DELETE /users/me/profile-image`, `GET /users/{id}/profile-image` 추가 (PRD 01 §7) |
| 관리자 화면 | SQLAdmin `/admin`, `users.role = 'ADMIN'`만. 공지 작성·문의 답변 |
| 공통 조각 | 헤더·푸터·로그인 모달은 `static/partials/` HTML 조각 + `includePartials()`. 새 페이지도 이 방식 |
| 작은 화면 | 폭 1280px 미만은 시퀀서를 열지 않고 안내 모달. 대시보드 Ready to start 배너 |
| 오류 페이지 | F-2 "숫자 자체가 신호" 7종 (`errors/`). 없는 페이지 → 404 화면, 없는 API → JSON 404 |
| 로고 | **S2 XOR Horn** — Nyxi 초승달 머리핀 + 위쪽 뿔에 걸친 반짝임, 겹친 곳 비움 (`static/assets/logo/mark.svg`, `favicon.svg`) |
| 홈 로딩 | **C Crescent** 약 1초, CSS만. -INF → 0 dB, 글꼴은 Unbounded(`display=block`). 첫 접속만 보이기는 `home.js initIntro`(사용자) |
| 커서 | 시퀀서 뺀 모든 페이지 **별 커서** (평소 흰색, 누르는 동안 보라). 입력칸·비활성은 원래 커서. 시퀀서 작업 영역에는 쓰지 않는 것을 추천 |
| 시퀀서 화면 | **사용자가 설계 문서를 따로 줌** → 받기 전에는 시퀀서 HTML/CSS를 만들지 않음 |
| 시퀀서 로딩 | B "Signal in" 바탕 목업: 진행률만큼 파형 → SIGNAL IN → **클릭 없이 바로** 위아래로 열림. 오디오는 시퀀서 안 첫 클릭·키 입력 때 `AudioContext.resume()`. 기존·새 프로젝트 두 경우 |

## 7. 사용자 성향 · 주의 사항
| 항목 | 내용 |
|---|---|
| 쉘 | Windows **PowerShell 5.1**. 안내 명령은 PowerShell 호환으로, `<` 리디렉션은 쓰지 않음. 경로는 저장소 루트(`StudioNx/`) 기준 |
| PR 병합 | 사용자가 `! gh pr merge N --merge`로 직접 병합 (AI의 병합 명령은 권한 검사에서 막힘) |

| 확인 방식 | 화면은 Chrome 헤드리스 + CDP로 캡처, 움직임은 실시간 녹화 MP4 (`docs/page_mockups/loader/_source/record.mjs`, `encode.py`). ffmpeg는 scratchpad에만 설치해 씀 |
| PDF 뷰어 | 한PDF로 열어 둔 PDF는 잠겨서 빌드가 덮어쓰지 못함 → 닫고 다시 빌드 |
| 요청 방식 | 수정 사항을 PDF(빨간 박스 주석)로 `frontend-reference/images/main page reference/`에 넣고 요청하기도 함. 짧은 지시("커밋하고 푸시 ㄱㄱ") |
| 비밀 정보 | `.env`, `docs/googlesheetAPI.txt`, `docs/studionx-*.json`은 git 제외. 내용을 출력하거나 커밋하지 않음 |
| 커밋 안 함 | `docs/page_mockups/38_http_status_poster.png` (사용자 결정) |
| 오래된 자료 | md·PDF·docx 중 하나만 갱신되는 실수가 있었음 → 함께 확인 |
