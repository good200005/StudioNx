## 1. 처음 상태

사용자가 "시퀀서 이전에 로딩 화면도 같이 넣었나?"라고 물으셔서 확인했습니다. 목업만 있고 구현은 없었습니다.

| 항목 | 상태 |
|---|---|
| 목업 | 있음. `docs/page_mockups/sequencer/04~07`(영상과 스토리보드)과 원본 `_source/loader.html` |
| 결정 | 인수인계 문서(2026-10-03, 04, 05)에 "B Signal in, 클릭 없이 바로 열림"으로 적혀 있음 |
| 구현 | 없음. `studioNx.html`에 로딩 요소가 없었고 시퀀서는 로딩 화면 없이 바로 나왔음 |
| 계획서 | 이 로딩을 맡은 작업이 없었음. 홈의 첫 접속 로딩(P1-20)과는 별개 |

## 2. 실행 결과

실제 시퀀서(헤드리스 Chrome)를 열고 로딩 화면의 상태를 60ms마다 기록했습니다.

| 확인한 장면 | 결과 |
|---|---|
| 첫 그림 | 로딩 화면이 23ms에 이미 떠 있음. 아래의 예시 화면이 먼저 비치지 않음 |
| 기존 프로젝트 (샘플 3개, 각 0.7초 지연) | 퍼센트가 0에서 100까지 줄지 않고 감. 샘플 개수가 `0/3`에서 `3/3`. 세 점이 차례로 켜짐. 100%가 되면 `SIGNAL IN`이 켜진 뒤 열림 |
| 샘플 하나 실패, 하나 2.5초 지연 | 멈추지 않고 열림. 실패한 샘플도 끝난 것으로 셈 |
| 새 프로젝트 (`&new=1`) | `NEW PROJECT`, 샘플을 받지 않음, 기존 프로젝트보다 짧음 |
| 예시 화면 (`projectId` 없음) | `EXAMPLE SCREEN`, 800ms 안팎 |
| 프로젝트 읽기 실패 | `NO SIGNAL`을 그대로 두고 열리며 안내 알림이 뜸 |
| 스크립트가 멈춘 상황 | CSS 안전장치가 30초 뒤에 화면을 풀어 줌 |
| 열린 뒤 재생 | 미리 받아 둔 샘플을 쓰고 서버에서 다시 받지 않음 |

화면은 `docs/screenshots/2026-10-21_s1-14_loader/`에 7장 있고, 목업과 같은 모양입니다.

## 4. 왜 이렇게 (이번 작업의 결정)

| 결정 | 이유 |
|---|---|
| 진행률이 실제 일의 진행이 되도록 샘플을 미리 받습니다 | 목업은 "샘플 n/34"를 보여 주는데, 이전의 시퀀서는 샘플을 재생을 누를 때 받았습니다. 열 때 프로젝트 데이터(`GET /full`) 하나만 받는 시간은 짧아서, 그대로 두면 진행률이 의미 없는 가짜 숫자가 됩니다. 미리 받으면 숫자가 진짜가 되고, 재생을 처음 누를 때도 기다리지 않습니다. |
| 로딩 화면은 열리는 것을 절대 막지 않습니다 | 샘플 하나의 실패나 지연, 프로젝트 읽기 실패, 25초 초과, 스크립트 정지 모두에서 열립니다. 시퀀서가 안 열리는 것이 가장 나쁜 결과라서입니다 (315 §4). |
| 목업의 시간표를 그대로 쓰되 실제 진행에 맞춥니다 | 목업은 고정 시간(기존 2.4초, 새 프로젝트 1.2초)이었습니다. 실제로는 불러오는 만큼 진행하고, 너무 빨리 끝나면 파형이 그려지는 모습이 안 보이므로 최소 표시 시간(1.6초, 1.1초, 0.8초)을 둡니다. 움직임 줄이기 설정에서는 최소 시간이 없습니다. |
| 마크업을 HTML에 처음부터 넣었습니다 | JS가 만들어 붙이면 그때까지 예시 화면이 먼저 보입니다. |
| 로딩 중에는 뒤 화면을 `inert`로 막습니다 | 보이지 않는 뒤 화면의 버튼에 Tab으로 들어가는 것을 막습니다. |
| 시험 도구가 기본으로 로딩 화면을 끕니다 | 로딩 화면이 화면 전체를 덮어서 기존 시험의 클릭이 막힙니다. 페이지가 열리기 전에 표시(`window.__snxNoLoader`)를 넣어 두고, 로딩 화면 시험만 이 표시를 넣지 않습니다. |
| 오디오 컨텍스트는 로딩 때 만들지 않습니다 | 브라우저 정책상 사용자의 조작 전에는 소리를 낼 수 없어서, 목업의 결정대로 재생을 누를 때 만들어집니다 (§7). |

## 5. 시험 중에 발견해서 고친 문제

| 문제 | 원인 | 고침 |
|---|---|---|
| 새 프로젝트와 예시 화면에서 첫 0.3초 동안 `OPENING PROJECT`가 보임 | 마크업의 기본 문구가 `OPENING PROJECT`이고, 스크립트가 종류를 정하는 것은 로딩 화면이 보이고 약 340ms 뒤였습니다. 그 사이에 기본 문구가 비쳤습니다. | CSS로 종류가 정해지기 전에는 종류 문구와 세 단계를 숨깁니다. 시험이 "정하기 전 표본(44개)은 숨겨져 있고 정한 뒤 표본(43개)은 보인다"를 확인합니다. |
| 시험이 이 문제를 잡지 못할 뻔함 | 고치는 도중 PowerShell로 시험을 수정하다 정규식의 역슬래시가 두 번 들어갔습니다(`\\b`). 그래서 "정하기 전 표본"이 늘 비어 있는 것으로 계산되어 엉뚱하게 실패했습니다. | 시험의 정규식을 바로잡았습니다. 코드의 오류가 아니라 시험의 오류였습니다. |
| 샘플이 없는 프로젝트에서 계획이 어긋남 | 샘플 수를 아직 모를 때를 "샘플 0개"로 보면 `NO SAMPLES`로 잠깐 바뀌어 깜빡입니다. | 샘플 수를 모를 때(`null`)와 0개를 구분했습니다. 모르면 샘플이 있는 것으로 봅니다. |

| 예시 화면의 제목과 정보 줄이 비어 허전함 | 예시 화면에는 프로젝트가 없어서 제목과 정보를 넣지 않았습니다. | `Example Project`와 `SAMPLE DATA, NOTHING IS SAVED`를 넣어 저장되지 않는 화면이라는 것을 알립니다. |
| Edge에서만 시험 한 건이 실패함 | CSS가 로드되기 전의 첫 표본은 기본값(`visible`)으로 읽혔습니다. 브라우저는 CSS가 올 때까지 화면을 그리지 않아서 사용자에게는 보이지 않는 순간이었고, 시험의 측정이 틀렸습니다. | CSS가 적용된 표본(`position: fixed`)만 판단하도록 시험을 고쳤습니다. Chrome과 Edge 모두 47건이 통과합니다. |

앱의 다른 부분의 오류는 없었습니다.

## 7. 알려진 한계

| 한계 | 내용 |
|---|---|
| `AUDIO ENGINE` 단계는 실제 엔진을 켜는 일이 아닙니다 | 브라우저 정책상 사용자의 조작 전에는 `AudioContext`가 소리를 낼 수 없어서, 컨텍스트는 재생을 누를 때 만들어집니다 (목업의 결정). 이 단계는 장치 화면이 그려질 때까지 기다리고 Web Audio를 쓸 수 있는지 확인하는 단계입니다. 목업의 문구를 그대로 쓴 것이라 이름이 실제보다 큰 약속처럼 보입니다. |
| 사용감은 직접 확인해야 합니다 | 시험은 헤드리스에서 상태와 시간을 기록해 확인했습니다. 열리는 속도와 느낌, 파형이 그려지는 모습이 마음에 드시는지는 실제 화면에서 보셔야 합니다. |
| 큰 프로젝트는 메모리를 씁니다 | 미리 받은 샘플은 재생이나 내보내기가 가져가기 전까지 메모리에 있습니다. 총량 한도 256MB를 넘는 샘플은 담지 않고 재생할 때 다시 받습니다. 한 번 가져가면 지웁니다. |
| 샘플 하나가 20초 넘게 걸리면 건너뜁니다 | 그 샘플은 재생할 때 다시 받습니다. 아주 느린 네트워크에서는 건너뛴 샘플이 많아질 수 있습니다. |
| `&new=1`이 주소에 남은 채 새로고침하면 `NEW PROJECT`로 보입니다 | 문구만 달라지고 샘플은 재생할 때 받습니다. 기능에는 문제가 없습니다. |
| 로컬 캐시(S2-11)와 겹칩니다 | 캐시가 생기면 샘플을 서버에서 받지 않고 캐시에서 읽게 되어 진행이 빨라집니다. 이 작업의 미리 받기는 그때 캐시를 읽는 쪽으로 바꾸면 됩니다. |
| 시퀀서만 있습니다 | 마이프로젝트 등 다른 페이지의 로딩은 이번 범위가 아닙니다 (홈의 첫 접속 로딩은 P1-20). |

## 9. 자주 받을 질문 대비 (Q/A)

**Q. 로딩 화면이 항상 1.6초 이상 보이나요?**
A. 기존 프로젝트는 그렇습니다. 샘플이 없어서 순식간에 끝나는 경우에도 파형이 그려지는 모습이 보이게 하려는 것입니다. 샘플이 느리게 오면 그만큼 더 걸립니다. 움직임 줄이기 설정이면 기다리지 않고 실제 진행만큼만 보입니다.

**Q. 로딩 중에 시퀀서를 조작할 수 있나요?**
A. 아닙니다. 로딩 화면이 화면 전체를 덮고, 뒤 화면은 Tab 키로도 들어갈 수 없게 막혀 있습니다. 끝나면 풀립니다.

**Q. 샘플이 하나 안 받아지면 어떻게 되나요?**
A. 열립니다. 그 샘플은 끝난 것으로 세고(그래서 `3/3`까지 감), 재생할 때 다시 받습니다. 샘플이 늦으면 20초까지 기다리고 건너뜁니다.

**Q. 시퀀서가 영영 안 열리는 일은 없나요?**
A. 세 겹의 보호가 있습니다. 샘플은 20초, 전체는 25초가 지나면 열고, 스크립트가 멈추는 경우에는 CSS가 30초 뒤에 화면을 풀어 줍니다.

**Q. 새 프로젝트도 샘플을 미리 받나요?**
A. 아니요. 방금 만든 프로젝트는 샘플이 없어서 받지 않고, 로딩이 더 짧습니다(최소 1.1초).
