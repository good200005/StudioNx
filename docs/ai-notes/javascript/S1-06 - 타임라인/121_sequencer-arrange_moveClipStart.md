## 1. 하는 일
클립을 좌우로 끌었을 때 **새 시작 tick**을 돌려줍니다. 끈 거리를 더해 격자에 맞추고, **마디 0 왼쪽으로는 못 갑니다**.

> 새 시작 = max(0, 격자에 맞춘 (지금 시작 + 끈 거리))

| 지금 시작 | 끈 거리 | 한 칸 | 새 시작 |
|---|---|---|---|
| 960 | 0 | 960 | 960 (제자리) |
| 960 | +1,000 | 960 | 1,920 |
| 960 | -700 | 960 | 0 |
| 0 | -5,000 | 960 | 0 (0 아래로 안 내려감) |
| 0 | 130 | 80 (1/16 셋잇단) | 160 |
| 0 | 130 | 1 (Alt, 격자 무시) | 130 |

## 2. 코드
```js
export function moveClipStart(startTick, deltaTicks, stepTicks) {
  return Math.max(0, snapTick(startTick + deltaTicks, stepTicks));
}
```
**최신 문법으로 쓰면** (공부용)
```js
export const moveClipStart = (startTick, deltaTicks, stepTicks) =>
  Math.max(0, snapTick(startTick + deltaTicks, stepTicks));
```
| 최신 문법 | 실제 코드 | 뜻 |
|---|---|---|
| 화살표 함수 | `function` 선언 | 같은 동작입니다 |

## 3. 왜 이렇게
| 선택 | 이유 |
|---|---|
| `snapTick()`을 그대로 씀 | 격자 맞추기가 한 곳에서 나옵니다. `stepTicks`가 0이면 그 함수가 던진 오류가 전해집니다 |
| `Math.max(0, …)` | 마디 0 왼쪽은 시간이 없는 곳입니다. 클립이 사라지지 않게 여기서 막습니다 |
| 오른쪽 끝 제한은 안 함 | 여러 클립을 함께 옮기면 어디까지 갈 수 있는지가 달라집니다(프로토타입도 묶음 전체로 계산). 그래서 부르는 쪽에서 맡습니다 |
| Alt(격자 무시)는 `stepTicks = 1` | 격자를 무시할 땐 한 칸을 1틱으로 주면 됩니다. 별도 함수 없이 같은 코드로 됩니다 |
| 격자 벗어난 시작도 붙임 | 시작이 격자 밖이면(예: 100) 끌지 않아도 가까운 칸으로 붙습니다 |

## 4. 시험 (Node에서 직접 실행, 12개 통과)
| 확인 | 결과 |
|---|---|
| 제자리(960+0), 오른쪽(960+1,000→1,920), 왼쪽(960-700→0) | ✔ |
| 0 아래로 못 감(0-5,000→0) | ✔ |
| 오프그리드 시작(100)이 격자 0으로 붙음 | ✔ |
| 셋잇단 칸(80), Alt(step 1)·Alt 음수 → 0 | ✔ |
| 여러 칸 이동(0+4,000→3,840) | ✔ |
| step 0·delta `NaN` → 오류 | ✔ |
