## 3. P1-28이 하는 일
로그인 모달의 `Can't sign in?`으로 열리는 계정 찾기 화면(Password 탭, Email 탭)과 `resetPassword.html`.
- **Password 탭**: 이메일을 받아 재설정 링크 메일을 보냅니다. 개발 중에는 실제로 보내지 않고 **서버 로그에 `[DEV MAIL] password reset link for r***@…: http://localhost:8000/resetPassword.html#token=<토큰>`**을 출력합니다(`MAIL_BACKEND=log`). 서버를 `--reload`로 켠 터미널(또는 `uvicorn.error` 로그)에서 볼 수 있습니다.
- **Email 탭**: 가입한 이메일을 잊은 경우. 가입된 `ACTIVE` 계정에만 안내 메일이 갑니다(문안 `app/services/mail_templates.py`, 목업 `docs/page_mockups/account_recovery/`). 가입되지 않은 주소에는 아무것도 보내지 않습니다(사용자 결정).
- 서버 응답은 **가입 여부와 관계없이 항상 같습니다**(202와 고정 문구). 횟수 제한은 이메일 3번, IP 10번(10분, 재설정과 안내가 따로, 서버 메모리).
- 비밀번호를 재설정하면 그 전에 발급된 로그인(액세스, 리프레시)이 모두 무효가 됩니다(`users.password_changed_at`과 토큰의 `iat` 비교, 초 단위).
- 재설정 성공 뒤 **자동 로그인은 하지 않습니다**(사용자 결정). 새 비밀번호로 직접 로그인합니다.

## 4. `resetPassword.html` (2026-10-15 완료, 아래는 당시 계획)
1. **목업을 먼저 만들어 사용자에게 보여 줍니다**(`docs/page_mockups/account_recovery/`). 로그인 전 페이지. 새 비밀번호 + 확인 입력, 비밀번호 규칙 표시(8~20자, 대문자, 소문자, 숫자, 특수기호 각 1개 이상, `static/js/core/password.js`의 `PASSWORD_RULES`와 `join.html`의 방식 참고), `Reset password` 버튼, 오류 상태(링크가 잘못되었거나 만료됨 → 다시 요청 안내, `Can't sign in?`으로 가는 링크), 성공 상태(자동 로그인 없음: `Sign In` 버튼으로 안내).
2. 정한 모양으로 **HTML과 CSS를 씁니다**. 공통 헤더, 푸터, 로그인 모달 조각을 `data-include`로 끼웁니다(`join.html` 참고). `<meta name="referrer" content="no-referrer">`를 둡니다.
3. **JS를 함수 하나씩** `static/js/pages/resetPassword.js`(또는 `core/`)에 만듭니다. 제안 순서:
   1. `#token=` 읽기: 주소의 `#token=<값>`을 읽고 **곧바로 주소창에서 지움**(`history.replaceState`, 토큰이 기록과 Referer로 새지 않게). 토큰이 없으면 오류 상태. 읽은 값은 메모리에만 둡니다(`localStorage` 금지).
   2. 비밀번호 규칙 실시간 표시와 확인 칸 일치 검사(`password.js`와 `join.js`의 `initPasswordRules` 참고)
   3. 폼 전송: `api.post('/auth/password-reset/confirm', { token, new_password })`. 성공하면 성공 화면. 400은 "링크가 잘못되었거나 만료되었습니다" + 다시 요청 안내, 422는 규칙 오류를 표시하고 **링크는 계속 쓸 수 있음**(토큰을 지우지 말 것), 429는 해당 없음, 연결 실패 문구. 위 §3 교훈 적용.
