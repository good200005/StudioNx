## 2. 시퀀서 / 작곡

### 2.1 오토메이션 레인 ⭐
- **내용**: 트랙 아코디언에 [오토메이션] 탭 추가. 볼륨·팬·디바이스 파라미터를 시간에 따라 바꾸는 선(포인트 + 곡선).
- **이유**: 필터 스윕, 빌드업, 페이드 인/아웃 없이 완성곡을 만들기 어렵습니다. 지금 PRD 02에서는 "추후 검토"로 빠져 있습니다.
- **DB 영향**: `automation_lanes(track_id, target_type, target_id, param_index)`, `automation_points(lane_id, tick, value, curve)` 테이블 추가.
- **난이도**: 중 (Web Audio `setValueAtTime`/`linearRampToValueAtTime`로 스케줄링)

### 2.2 스케일 · 코드 도우미
- **내용**: 피아노롤에서 키/스케일을 고르면 스케일 밖 음을 흐리게 표시, "코드 스탬프"(클릭 한 번에 메이저/마이너 코드 입력), 노트 스냅 to 스케일.
- **이유**: 입문 사용자 대상(PRD 00 §2)에 잘 맞고, Phase 5의 키 분석 결과와도 연결됩니다(레퍼런스 키를 그대로 적용).
- **난이도**: 하

### 2.3 오디오 녹음 (마이크/오디오 인터페이스)
- **내용**: `getUserMedia`로 오디오 트랙에 녹음, 입력 모니터링, 레이턴시 보정.
- **이유**: 보컬·기타를 쓰는 사용자에게 필수. `samples.source='RECORDING'` 자리가 이미 있습니다.
- **난이도**: 중 (레이턴시 보정이 까다로움)

### 2.4 패턴 / 클립 런처
- **내용**: FL Studio의 패턴, Ableton의 세션 뷰처럼 "짧은 패턴을 만들어 타임라인에 반복 배치". 원본 패턴을 고치면 모든 복사본이 함께 바뀜(링크된 클립).
- **이유**: 비트메이커 작업 방식(PRD 00 페르소나)에 잘 맞고, FL·Ableton을 융합하는 Studio Nx 콘셉트와도 일치합니다.
- **DB 영향**: `patterns` 테이블 + `clips.pattern_id`.
- **난이도**: 중

### 2.5 템플릿 프로젝트
- **내용**: 장르별 시작 템플릿(트랙 구성 + 디바이스 체인 + BPM). AI 레퍼런스 분석 결과로 "이 레퍼런스 기반 새 프로젝트 만들기"도 가능.
- **난이도**: 하

## 3. 시퀀서 캐릭터 · Gopher

### 3.1 캐릭터를 Gopher의 얼굴로 ⭐
- **내용**: Gopher 답변이 오면 캐릭터가 말풍선으로 요약을 말하고, 클릭하면 하단 패널 Gopher 탭이 열림. 캐릭터에게 직접 말 걸기(캐릭터 클릭 → 짧은 입력창).
- **이유**: 두 기능이 따로 노는 것보다 "도와주는 캐릭터"라는 하나의 정체성이 생깁니다. FL Chan과의 차별점이 됩니다.
- **난이도**: 하 (FR-285, FR-539를 연결하는 정도)

### 3.2 상황 인지 팁 (프로액티브 도움)
- **내용**: 클리핑 발생, 마스터 LUFS가 너무 높음, 같은 주파수 대역 충돌 등을 감지하면 캐릭터가 먼저 팁을 줌. 끄기 옵션 필수.
- **이유**: "질문할 줄 모르는" 입문자에게 특히 유용합니다.
- **난이도**: 중 (감지 규칙 설계)

### 3.3 튜토리얼 모드
- **내용**: 첫 접속 시 캐릭터가 "샘플 끌어오기 → 노트 찍기 → 이펙트 넣기 → 출력"을 단계별 안내.
- **난이도**: 하

## 4. 협업

### 4.1 타임라인 코멘트 ⭐
- **내용**: 특정 마디/클립에 댓글 핀 꽂기, 스레드 답글, 해결 처리. 톡방에 "OO님이 12마디에 코멘트" 시스템 메시지.
- **이유**: 음악 피드백은 "2:15쯤 베이스가…"처럼 **위치**에 붙는 경우가 대부분입니다.
- **DB 영향**: `timeline_comments(project_id, user_id, tick, track_id, content, resolved_at)`.
- **난이도**: 중

### 4.2 버전 스냅샷 · 복원 ⭐
- **내용**: 수동 스냅샷("믹스 v1") + 자동 스냅샷(하루 1회), 목록에서 미리듣기·복원·복제.
- **이유**: 동시 편집과 AI 추천 일괄 적용은 되돌리고 싶은 순간을 만듭니다. Undo는 세션 단위라 한계가 있습니다.
- **DB 영향**: `project_snapshots(project_id, revision, name, data JSON, created_by)`.
- **난이도**: 중

### 4.3 트랙 잠금 · 담당자 표시
- **내용**: "이 트랙은 내가 작업 중" 잠금, 트랙별 담당 멤버 아바타.
- **이유**: 동시 편집 충돌을 기술이 아니라 **사람끼리의 약속**으로 줄이는 가장 싼 방법입니다.
- **난이도**: 하

## 5. 공유 · 커뮤니티

### 5.1 공개 재생 페이지 (읽기 전용 링크)
- **내용**: 출력 결과를 공개 링크로 공유(파형 플레이어 + 코멘트). 로그인 없이 감상 가능, 만료·비공개 설정.
- **이유**: 협업자가 아닌 사람(친구, 클라이언트)에게 들려주는 경로가 현재 없습니다.
- **난이도**: 중

### 5.2 프리셋 · 샘플 공유
- **내용**: 내 프리셋/샘플팩을 다른 회원과 공유, AI 추천 프리셋 중 인기 있는 것 모아보기.
- **주의**: 저작권·신고 기능 필요.
- **난이도**: 중~상

## 6. 기술 · 운영

### 6.1 샘플 로컬 캐시 (OPFS / IndexedDB)
- **내용**: 한 번 받은 샘플·파형을 브라우저에 캐시, 프로젝트 재오픈 속도 향상, 오프라인에서도 열기 가능.
- **난이도**: 하~중

### 6.2 저장 용량 · 사용량 관리
- **내용**: 사용자별 저장 용량 표시·한도, 오래된 출력 파일 자동 정리, AI 사용량(분석·Gopher) 표시.
- **이유**: 악기 분리(stem 수만큼 용량 증가)와 AI 비용 때문에 운영상 꼭 필요해집니다.
- **DB 영향**: `users`에 `storage_used_bytes` 또는 집계 뷰.
- **난이도**: 하

### 6.3 오디오 회귀 테스트 (골든 파일)
- **내용**: 테스트용 프로젝트를 렌더링해 기준 WAV와 비교(오차 허용). 엔진·플러그인 수정 후 소리가 바뀌었는지 자동 확인.
- **이유**: DAW는 "소리가 조용히 달라지는" 버그가 가장 위험합니다. Sentry로는 잡히지 않습니다.
- **난이도**: 중

### 6.4 Sentry 활용 확장
- **내용**: 오디오 엔진의 언더런(끊김) 횟수, WebSocket 재접속 횟수, AI 응답 시간 등을 Sentry 커스텀 이벤트/성능 지표로 수집. Session Replay는 개인정보 마스킹 후 제한적으로.
- **난이도**: 하

### 6.5 키보드 단축키 · 커맨드 팔레트
- **내용**: Ctrl+P로 모든 명령 검색·실행(트랙 추가, 디바이스 삽입, 출력 등), 단축키 사용자 지정.
- **이유**: 숙련자 속도 향상 + Gopher 액션 버튼과 같은 "명령" 체계를 공유할 수 있습니다.
- **난이도**: 하~중

## 7. C++ 학습 관점 제안
- **같은 DSP 코드를 두 곳에서**: JUCE로 만든 DSP 클래스를 ① 데스크톱 VST3 플러그인(학습·테스트용)과 ② WASM 빌드(Studio Nx) 양쪽에서 쓰도록 구조를 잡으면, JUCE 학습과 서비스 개발이 한 번에 됩니다.
- **추천 학습 순서**: Gain → Biquad 필터(EQ) → 컴프레서(엔벨로프 팔로워) → 오실레이터(안티앨리어싱) → 간단한 신스 → 리버브. PRD 02의 기본 플러그인 순서와 맞춰 두면 웹 버전을 하나씩 C++ 버전으로 교체할 수 있습니다.
- **비교 측정**: 같은 플러그인의 Web Audio 버전과 WASM 버전 CPU 사용량을 비교해 기록해 두면 포트폴리오·발표 자료로 좋습니다.
