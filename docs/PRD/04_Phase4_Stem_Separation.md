# Studio Nx — PRD 04. Phase 4: 악기 분리 (Instrument / Stem Separation)

| 항목 | 내용 |
|---|---|
| 기획서 기능 | 4) 샘플 등을 별도로 instrument separation하는 기능 |
| 선행 Phase | Phase 2 (샘플 라이브러리) |
| 관련 페이지 | `studioNx.html` (라이브러리 패널, 분리 모달) |
| 전체 개요 | [00_PRD_Overview.md](00_PRD_Overview.md) |

---

## 1. 목표 / 배경
- 라이브러리에 있는 오디오(완성곡, 루프, 샘플)를 **보컬·드럼·베이스·기타 등 악기별 stem으로 분리**해, 각각을 새 샘플로 쓸 수 있게 합니다.
- 예: 드럼 루프만 뽑아 쓰기, 보컬을 빼고 반주만 남기기, 레퍼런스 곡의 베이스 라인만 들어보기.
- 분리 결과는 **일반 샘플과 똑같이** 라이브러리에 등록되므로, 시퀀서·출력·AI 분석 기능을 그대로 재사용합니다.

## 2. 범위
### In scope
- 라이브러리 샘플 선택 → 분리 모드 선택 → 서버 비동기 분리 → 결과 stem들을 라이브러리에 자동 등록
- 분리 모드: 2-stem(보컬/반주), 4-stem(보컬/드럼/베이스/기타), 6-stem(+기타/피아노)
- 작업 진행 상태 표시, 작업 목록, 실패 시 재시도
- 분리 결과를 타임라인에 바로 트랙으로 펼치기(선택)

### Out of scope
- 실시간(재생 중) 분리 → 지원하지 않음
- 드럼 내부 세부 분리(킥/스네어/하이햇) → 추후 검토
- 분리 모델 직접 학습 → 지원하지 않음 (사전 학습 모델 사용)

## 3. 사용자 스토리
| ID | 사용자 스토리 |
|---|---|
| US-401 | 사용자로서, 라이브러리의 곡을 우클릭해 "악기 분리"를 누르면 stem들이 생기길 원한다. |
| US-402 | 사용자로서, 분리가 오래 걸려도 다른 작업을 계속하고, 끝나면 알림을 받고 싶다. |
| US-403 | 사용자로서, 분리된 stem들을 한 번에 타임라인 트랙들로 펼치고 싶다. |

## 4. 기능 요구사항
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-401 | 라이브러리 샘플 컨텍스트 메뉴 → "악기 분리" → 모드 선택 모달(2/4/6-stem, 예상 소요시간 안내) | 필수 |
| FR-402 | 작업 생성 시 `separation_jobs`에 `PENDING`으로 저장 후 **백그라운드 작업 큐**에서 처리 (API는 즉시 응답) | 필수 |
| FR-403 | 분리 엔진: 사전 학습 모델(후보: **Demucs / HT-Demucs** 계열) 사용, `model_name`에 기록 | 필수 |
| FR-404 | 진행 상태: `PROCESSING` 중 진행률 갱신, 클라이언트는 폴링(또는 Phase 6 이후 WebSocket 알림) | 필수 |
| FR-405 | 완료 시 stem별 파일을 저장하고 각각 `samples`에 `source='SEPARATION'`으로 등록, `separation_stems`에 연결. 이름 규칙: `{원본이름} - {Vocals}` | 필수 |
| FR-406 | 결과 stem들에 자동 태그(예: INSTRUMENT 카테고리의 `Vocals`, `Drums`) 부여 | 권장 |
| FR-407 | "타임라인에 펼치기": 각 stem을 새 AUDIO 트랙 + 같은 시작 위치 클립으로 배치 | 권장 |
| FR-408 | 작업 목록: 진행 중/완료/실패, 실패 시 오류 메시지와 [재시도] | 필수 |
| FR-409 | 제한: 원본 길이 최대 10분, 사용자당 동시 작업 1~2개 (설정값) | 필수 |
| FR-410 | 원본 샘플이 삭제(소프트)되어도 이미 만들어진 stem은 유지 | 필수 |
| FR-411 | 작업 생성 전 **예상 결과 용량**(원본 크기 × stem 수)을 남은 저장 용량과 비교, 부족하면 생성 거부 + [용량 정리] 안내 (PRD 01 §4.4) | 필수 |

## 5. 비기능 요구사항
| 구분 | 요구사항 |
|---|---|
| 처리 환경 | 분리는 연산량이 크므로 **별도 워커 프로세스**에서 실행. GPU가 있으면 사용, 없으면 CPU (느림을 UI에 안내) |
| 처리 시간 | 3분 곡 4-stem 기준 CPU에서 수 분 이내 목표 (환경에 따라 측정 후 조정) |
| 안정성 | 워커가 죽어도 작업이 `PROCESSING`에 영원히 머무르지 않도록 타임아웃 → `FAILED` 처리 |
| 품질 | 결과 stem의 샘플레이트·길이는 원본과 동일 |
| 저장공간 | stem은 원본 크기 × stem 수만큼 용량이 늘어나므로, 사용자별 저장 용량 표시 고려 |
| 권리 | 업로드/분리 대상 음원의 저작권 책임은 사용자에게 있음을 이용약관·UI에 안내 |

## 6. 화면 구성
- 라이브러리 패널: 샘플 우클릭 → "악기 분리"
- 분리 모달: 모드 선택(그림으로 stem 구성 표시) → [분리 시작]
- 라이브러리 상단 "작업" 배지: 진행 중 작업 수 표시, 클릭 시 작업 목록(진행률 바)
- 완료 토스트: "OO 분리가 완료되었습니다 [타임라인에 펼치기]"

## 7. API 초안 (FastAPI)
| Method | Path | 설명 |
|---|---|---|
| POST | `/separations` | 분리 작업 생성 (body: `source_sample_id`, `stem_mode`) |
| GET | `/separations?status=` | 내 분리 작업 목록 |
| GET | `/separations/{id}` | 상태·진행률·결과 stem 목록 |
| POST | `/separations/{id}/retry` | 실패 작업 재시도 |
| DELETE | `/separations/{id}` | 작업 기록 삭제 (stem 샘플은 유지) |

워커 측 (내부 함수, 템플릿만):
- `run_separation(separation_id)` — 원본 로드 → 모델 추론 → stem 저장 → `samples`/`separation_stems` INSERT → 상태 갱신

## 10. 완료 기준 (Acceptance Criteria)
- [ ] 라이브러리 샘플을 4-stem 모드로 분리하면 4개의 새 샘플이 라이브러리에 생긴다.
- [ ] 분리 진행 중에도 시퀀서 편집·재생이 가능하다.
- [ ] stem 4개를 동시에 재생하면 원본과 거의 같은 소리가 난다.
- [ ] 실패한 작업은 오류 메시지가 보이고 재시도할 수 있다.
- [ ] 다른 회원의 샘플로는 분리 작업을 만들 수 없다.
- [ ] "타임라인에 펼치기"로 stem 수만큼 트랙이 생성된다.
