| 항목 | 내용 |
|---|---|
| 기획서 기능 | 1) 기본적인 회원 등의 CRUD 기능 |
| 선행 Phase | 없음 |
| 관련 페이지 | `home.html`(로그인 모달 포함), `join.html`, `myPage.html`, `userInfo.html`, `myProject.html` |
| 전체 개요 | [00_PRD_Overview.md](00_PRD_Overview.md) |

## 1. 목표 / 배경
- 서비스의 입구(홈)와 회원 체계를 만들어, 이후 모든 기능(샘플 라이브러리, 프로젝트, 협업)이 **"누구의 데이터인가"** 를 기준으로 동작할 수 있게 합니다.
- 프로젝트 목록 CRUD까지 이 단계에서 만들어, Phase 2 시퀀서가 "프로젝트를 열고 저장"하는 대상이 미리 존재하도록 합니다.

## 2. 범위
### In scope
- 회원가입 / 로그인 / 로그아웃 / 회원정보 조회·수정 / 비밀번호 변경 / 회원 탈퇴
- 인증 상태 유지 (JWT 기반, 아래 FR-105 참고)
- 홈 화면 서비스 소개 + 문의 접수
- 마이페이지 대시보드
- 나의 프로젝트 목록: 생성, 이름·설명 수정, 삭제, 열기(→ `studioNx.html` 이동)

### Out of scope (이후 Phase 또는 추후 검토)
- 소셜 로그인 **연동**(Google·Discord·SoundCloud — 버튼 자리만 Phase 1에 둠, FR-110), 이메일 인증, 비밀번호 찾기 메일 발송 → 추후 검토
- 관리자 문의 답변 화면 → 추후 검토 (DB 컬럼은 미리 준비)
- 공유받은 프로젝트 목록 → Phase 6

## 4. 기능 요구사항
### 4.1 회원 (users)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-101 | 회원가입: 이메일, 비밀번호(+확인), 닉네임(2~20자) 입력. 이메일·닉네임 중복 검사(입력 중 실시간 확인 API 제공) | 필수 |
| FR-102 | 비밀번호 규칙: **8~20자, 대문자·소문자·숫자·특수기호(키보드 기호 `!@#$%^&*` 등) 각 1개 이상. 영문·숫자·키보드 기호만 사용(한글·공백 불가)**. 가입 화면에 조건 목록을 보여 주고 입력할 때마다 만족한 조건을 ✓로 표시. 서버에서도 같은 규칙으로 다시 검사한 뒤 bcrypt로 해시 저장 | 필수 |
| FR-103 | 로그인: `home.html`의 **로그인 모달**에서 이메일+비밀번호 확인 후 토큰 발급, `last_login_at` 갱신. 실패 시 "이메일 또는 비밀번호가 올바르지 않습니다"로 통일된 메시지. 별도 로그인 페이지는 두지 않음 | 필수 |
| FR-104 | 로그아웃: 클라이언트 토큰 삭제 (+ 리프레시 토큰 쿠키 삭제) | 필수 |
| FR-105 | 인증 방식: **Access Token(JWT, 30분) + Refresh Token(HttpOnly 쿠키)**. 로그인이 필요한 페이지는 토큰이 없으면 `home.html#login?next=<원래 페이지>`로 이동 → 로그인 모달이 자동으로 열리고, 로그인 후 원래 페이지로 돌아감 | 필수 |
| FR-109 | 자동 로그인: 로그인 모달의 **[자동 로그인] 체크박스**. 체크하면 리프레시 쿠키에 만료일(**3일**)을 지정해 브라우저를 닫아도 유지, 체크하지 않으면 세션 쿠키(브라우저를 닫으면 로그아웃). 다시 접속하면 `home.html`이 열리고(자동 이동 없음) 헤더가 로그인 상태로 바뀜(FR-111) | 필수 |
| FR-110 | 소셜 로그인 버튼 자리: 로그인 모달과 `join.html`에 Google·Discord·SoundCloud 버튼. 평소 단색, 마우스를 올리면 각 서비스 색. **연동은 추후** — 지금은 누르면 "준비 중" 안내. 연동할 때 `users.password_hash` NULL 허용 + 소셜 계정 연결 테이블 추가 필요 | 권장 |
| FR-106 | 회원정보 조회/수정: 닉네임, 프로필 이미지 변경. 이메일은 변경 불가 | 필수 |
| FR-107 | 비밀번호 변경: 현재 비밀번호 확인 후 변경 | 필수 |
| FR-108 | 회원 탈퇴: 비밀번호 재확인 → `status='DELETED'`, `deleted_at` 기록(소프트 삭제). 탈퇴 계정은 로그인 불가 | 필수 |

## 5. 비기능 요구사항
- 비밀번호·토큰은 로그에 남기지 않습니다.
- 모든 프로젝트 API는 **요청자가 해당 프로젝트의 멤버인지** 확인합니다(`project_members` 기준).
- 프로필 이미지: jpg/png/webp, 최대 2MB.
- 입력값 검증은 프론트(UX용)와 백엔드(보안용) **양쪽 모두** 수행.

## 7. API 초안 (FastAPI)
> 경로 prefix: `/api/v1`. 구현 없이 라우터·스키마 템플릿만 제공 예정.

| Method | Path | 설명 | 인증 |
|---|---|---|---|
| POST | `/auth/signup` | 회원가입 | - |
| GET | `/auth/check-email?email=` | 이메일 중복 확인 | - |
| GET | `/auth/check-nickname?nickname=` | 닉네임 중복 확인 | - |
| POST | `/auth/login` | 로그인 → access token + refresh 쿠키 | - |
| POST | `/auth/refresh` | access token 재발급 | refresh 쿠키 |
| POST | `/auth/logout` | 로그아웃 | ✔ |
| GET | `/users/me` | 내 정보 | ✔ |
| PATCH | `/users/me` | 닉네임 등 수정 | ✔ |
| POST | `/users/me/profile-image` | 프로필 이미지 업로드 (multipart) | ✔ |
| PUT | `/users/me/password` | 비밀번호 변경 | ✔ |
| DELETE | `/users/me` | 회원 탈퇴 (body: 비밀번호) | ✔ |
| POST | `/inquiries` | 문의 등록 (email, title, content, privacy_agreed) | 선택 |
| GET | `/dev-notes?limit=4` | 공개된 공지 목록 (최신순) | - |
| GET | `/dev-notes/{note_id}` | 공지 상세 | - |
| — | `/admin` | SQLAdmin 관리자 화면 (dev_notes·inquiries 등 관리) | ADMIN |
| GET | `/projects?query=&page=&size=` | 내 프로젝트 목록 | ✔ |
| POST | `/projects` | 프로젝트 생성 | ✔ |
| GET | `/projects/{project_id}` | 프로젝트 기본 정보 | ✔ 멤버 |
| PATCH | `/projects/{project_id}` | 제목·설명 수정 | ✔ OWNER/EDITOR |
| DELETE | `/projects/{project_id}` | 프로젝트 삭제 | ✔ OWNER |
| GET | `/me/dashboard` | 대시보드 요약 (용량·AI 사용량 포함) | ✔ |
| GET | `/me/storage` | 저장 용량 상세 (종류별 사용량, 큰 파일 목록) | ✔ |
| GET | `/users/me/settings` · PATCH | 환경 설정 조회·저장 (PRD 02 §7) | ✔ |

## 10. 완료 기준 (Acceptance Criteria)
- [ ] 회원가입 → 로그인 → 마이페이지 진입이 정상 동작한다.
- [ ] 중복 이메일/닉네임으로는 가입할 수 없다.
- [ ] DB에 비밀번호가 평문으로 저장되지 않는다.
- [ ] 로그인하지 않은 상태로 `myPage.html` 등에 접근하면 `home.html`로 이동해 로그인 모달이 열리고, 로그인 후 원래 페이지로 돌아간다.
- [ ] [자동 로그인]을 체크하면 브라우저를 닫았다 열어도 3일 동안 로그인이 유지되고, 체크하지 않으면 유지되지 않는다.
- [ ] 로그인 상태로 `home.html`에 들어오면 헤더 버튼이 My Page / My Projects로 보인다.
- [ ] 회원정보·비밀번호 수정, 탈퇴가 동작하고, 탈퇴한 계정은 로그인되지 않는다.
- [ ] 홈 문의 폼 제출 시 `inquiries`에 저장된다.
- [ ] 프로젝트 생성/목록/수정/삭제가 동작하고, 생성 시 `project_members`에 OWNER 행이 생긴다.
- [ ] 다른 회원의 프로젝트는 API로도 조회·수정·삭제할 수 없다.
- [ ] 대시보드에 저장 용량과 AI 사용량이 표시되고, 한도를 넘으면 업로드가 막힌다.
- [ ] 환경 설정에서 테마를 바꾸면 모든 페이지에 적용되고 다음 로그인에도 유지된다.
