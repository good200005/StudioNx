## 1. 목표 / 배경
- 파일을 주고받지 않고, **하나의 프로젝트를 여러 회원이 동시에 열어 편집**할 수 있게 합니다. 한 사람이 클립을 옮기면 다른 사람 화면에도 곧바로 반영됩니다.
- 프로젝트마다 **단체 채팅방**을 두어 작업하면서 바로 의견을 나눌 수 있게 합니다.

## 2. 범위
### In scope
- 초대: 이메일(또는 닉네임)로 초대, 초대 링크, 수락/거절, 권한 지정(EDITOR / VIEWER)
- 멤버 관리: 권한 변경, 내보내기, 나가기
- 실시간 동시 편집: 트랙·클립·노트·플러그인 파라미터·프로젝트 설정 변경을 실시간 동기화
- 접속자 표시(Presence): 접속 중인 멤버 아바타, 각자의 재생 헤드/선택 영역 색상 표시
- 프로젝트별 단체 채팅: 실시간 메시지, 이전 메시지 불러오기, 시스템 메시지(입장, 초대 수락 등), 안 읽은 메시지 수
- 변경 이력 저장(누가 언제 무엇을 바꿨는지)
- **타임라인 코멘트**: 마디·트랙·클립 위치에 댓글 핀, 스레드 답글, 해결 처리
- **버전 스냅샷 · 복원**: 수동/자동 스냅샷, 미리듣기, 복원, 새 프로젝트로 복제
- **트랙 잠금 · 담당자 표시**

### Out of scope
- 음성/영상 통화 → 지원하지 않음
- 재생 동기화(모두가 같이 듣기) → 추후 검토
- 채팅 파일 첨부, 이모지 반응 → 추후 검토

### 4.2 실시간 동시 편집
| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-611 | 프로젝트를 열면 **WebSocket**(`/ws/projects/{id}`)으로 접속. 인증 토큰 + 멤버 권한 확인 | 필수 |
| FR-612 | 편집은 **변경 연산(operation)** 단위로 전송. 예: `clip.move {clip_id, start_tick}`, `note.add {...}`, `param.set {track_plugin_id, index, value}`, 패처 연결 `link.add` / `link.remove`, `track.routing_mode` | 필수 |
| FR-613 | **서버가 순서를 정하는 방식(중앙 서버 순서화)**: 서버가 연산을 받아 검증 → DB 반영 → `projects.revision` +1 → `project_change_logs` 기록 → 모든 접속자에게 브로드캐스트 | 필수 |
| FR-614 | 충돌 처리: 클라이언트는 자기 연산을 먼저 화면에 반영(낙관적 적용)하고, 서버 확정 순서와 다르면 서버 기준으로 재적용. 같은 속성 동시 수정은 **마지막에 도착한 값이 우선(LWW)** | 필수 |
| FR-615 | 삭제된 대상에 대한 연산(예: 다른 사람이 지운 클립 이동)은 서버에서 거부하고 해당 클라이언트에 알림 | 필수 |
| FR-616 | 재접속: 마지막으로 받은 `revision` 이후 변경분을 `project_change_logs`에서 받아 따라잡기. 차이가 너무 크면 전체 상태 다시 로드 | 필수 |
| FR-617 | 연속 변경(노브 돌리기, 드래그 중)은 일정 간격(예: 50ms)으로 묶어 전송, 드래그 종료 시 최종값 확정 | 필수 |
| FR-618 | Undo/Redo는 **자기 연산만** 되돌림 (다른 사람 작업을 되돌리지 않음) | 권장 |
| FR-619 | VIEWER의 편집 연산은 서버에서 거부, UI에서도 편집 도구 비활성화 | 필수 |
| FR-620 | 샘플 공유: 멤버가 타임라인에 올린 샘플은 다른 멤버도 재생 가능해야 함(프로젝트에 사용된 샘플은 멤버에게 읽기 권한) | 필수 |

> 참고: 더 정교한 방식으로 CRDT(Yjs 등)나 OT를 검토할 수 있으나, 시퀀서 데이터는 대부분 "객체 속성 변경"이라 **서버 순서화 + LWW**로 시작하고 필요 시 확장합니다.

### 4.6 버전 스냅샷 · 복원
> Undo(세션 내 명령 단위)와 변경 이력(연산 로그)으로는 "며칠 전 상태로 통째로 돌아가기"가 어렵습니다. 스냅샷은 **프로젝트 전체 상태의 저장본**입니다. 상세 설명: [Ai_feedback_moreExplain.md](../Ai_feedback_moreExplain.md) §2

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-661 | **수동 스냅샷**: [스냅샷 저장] → 이름 입력(예: "믹스 v1"). OWNER/EDITOR 가능 | 필수 |
| FR-662 | **자동 스냅샷**: ① 하루 1회(그날 변경이 있을 때) ② 위험 작업 직전 — 스냅샷 복원 직전(`BEFORE_RESTORE`), 템플릿 교체 적용 직전(`BEFORE_TEMPLATE`), AI 추천 일괄 적용 직전(`BEFORE_AI_APPLY`) | 필수 |
| FR-663 | 저장 내용: 프로젝트 전체 상태(트랙·디바이스·연결선·패턴·노트·오토메이션·설정)를 압축 JSON 파일로 저장(`data_path`). **샘플 오디오 파일은 복사하지 않고 참조**만 함 | 필수 |
| FR-664 | 스냅샷 목록: 이름, 종류, 만든 사람, 시각, revision. 고정(📌) 가능 | 필수 |
| FR-665 | **미리듣기**: 스냅샷 시점 상태를 오프라인 렌더링해 짧은 미리듣기 생성(요청 시 생성 후 캐시, `preview_path`) | 권장 |
| FR-666 | **복원**: 확인창 → 현재 상태를 `BEFORE_RESTORE`로 자동 저장 → 스냅샷 상태로 교체. 협업 중이면 서버가 `project.restore` 연산으로 처리해 **모든 접속자에게 동시에 반영**, revision 증가. OWNER/EDITOR만 | 필수 |
| FR-667 | **새 프로젝트로 복제**: 스냅샷 시점 상태로 새 프로젝트 생성(원본은 그대로) — 두 버전 비교용 | 필수 |
| FR-668 | **보관 규칙**: 수동·고정 스냅샷은 삭제 전까지 보관 / 자동 스냅샷은 최근 7일치 일일 + 최근 4주치 주간 1개씩 + 위험 작업 직전 스냅샷 30일 보관 후 정리. 스냅샷 파일도 저장 용량에 포함 | 필수 |
| FR-669 | 스냅샷이 참조하는 샘플은 삭제(소프트) 후에도 파일을 지우지 않음 — 참조하는 스냅샷이 모두 정리된 뒤에 실제 파일 삭제 | 필수 |

## 5. 비기능 요구사항
| 구분 | 요구사항 |
|---|---|
| 지연 | 같은 지역 기준 한 사람의 편집이 다른 사람 화면에 반영되기까지 300ms 이내 목표 |
| 동시 접속 | 프로젝트당 동시 편집자 최대 8명 (설정값) |
| 일관성 | 모든 접속자의 최종 상태가 서버 DB 상태와 동일하게 수렴할 것 |
| 확장성 | 서버 1대 기준으로 시작. 다중 서버 확장 시 메시지 브로커(예: Redis Pub/Sub) 도입 검토 |
| 보안 | WebSocket 연결·모든 연산마다 권한 검사. 초대 토큰은 추측 불가능한 랜덤 64자, 1회 사용 |
| 이력 보관 | `project_change_logs`는 용량이 커지므로 일정 기간/개수 이후 정리 정책 마련 |

  - 타임라인: 다른 멤버의 선택 영역/커서를 색상으로 표시
- `myPage.html`: "받은 초대" 위젯 (수락/거절)
- `myProject.html`: "내 프로젝트 | 공유받은 프로젝트" 탭, 카드에 멤버 수·안 읽은 메시지 수·미해결 코멘트 수

## 10. 완료 기준 (Acceptance Criteria)
- [ ] 이메일로 초대 → 상대가 마이페이지에서 수락 → 공유받은 프로젝트 목록에 나타난다.
- [ ] 두 브라우저에서 같은 프로젝트를 열고 한쪽에서 클립을 옮기면 다른 쪽에 즉시 반영된다.
- [ ] 두 명이 같은 노브를 동시에 돌려도 최종적으로 양쪽 값이 같아진다.
- [ ] 한쪽이 지운 클립을 다른 쪽이 옮기려 하면 거부되고 화면이 서버 상태로 맞춰진다.
- [ ] 네트워크를 끊었다 다시 연결하면 그 사이 변경분을 따라잡는다.
- [ ] VIEWER는 재생·채팅만 가능하고, 편집 연산을 강제로 보내도 서버가 거부한다.
- [ ] 채팅 메시지가 실시간으로 오가고, 새로고침 후에도 이전 메시지가 보인다.
- [ ] 접속 중인 멤버 아바타가 표시되고, 나가면 사라진다.
- [ ] 32마디에 코멘트를 달면 다른 멤버 화면에 핀이 나타나고, 답글·해결 처리가 동작한다. VIEWER도 코멘트를 달 수 있다.
- [ ] 수동 스냅샷을 만들고 편집을 계속한 뒤 복원하면, 모든 접속자 화면이 스냅샷 상태로 바뀌고 복원 직전 상태가 자동 스냅샷으로 남는다.
- [ ] 스냅샷을 새 프로젝트로 복제하면 원본은 그대로다.
- [ ] 잠긴 트랙은 잠근 사람 외에는 편집할 수 없고(서버도 거부), OWNER는 강제 해제할 수 있다.
