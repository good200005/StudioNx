# Studio Nx — AI용 문서 작성 매뉴얼 (템플릿 · 빌드)

| 항목 | 내용 |
|---|---|
| 대상 | 이 저장소에서 문서를 만드는 **AI** (Claude 등) |
| 목적 | 어느 컴퓨터에서든 기존 문서와 **같은 템플릿·같은 모양**으로 md + PDF(+ docx)를 만들기 |
| 작성일 | 2026-10-02 |

> **AI에게:** 문서 작성 요청을 받으면 이 파일을 먼저 끝까지 읽고 그대로 따르세요. 기존 문서(`docs/PRD/*.md`, `docs/DB.md`, `docs/Git_Manual.md`)가 실제 예시입니다. 모양이 애매하면 가장 비슷한 기존 문서를 열어 같은 구조를 쓰세요.

## 1. 필요한 환경
| 도구 | 용도 | 확인 |
|---|---|---|
| Node.js 18+ | PDF·ERD 빌드 스크립트 실행 | `node --version` |
| Google Chrome (또는 Edge) | 헤드리스 렌더링 → PDF / PNG | `build.js`가 기본 설치 경로에서 자동 탐색 |
| 인터넷 | CDN에서 `marked`(md 변환), `mermaid`(간트), `@viz-js/viz`(ERD) 로드 | — |
| (docx만) `docx` npm | md → Word 변환 | `studionx/db/docs/_build`에서 `npm install` |
| (검증용, 선택) Python `pypdf` | PDF 페이지 수·내용 확인 | `pip install pypdf` |

- 한글 글꼴: Windows는 **맑은 고딕**, macOS는 Apple SD Gothic Neo로 자동 대체됩니다.
- Chrome 경로가 다르면 `docs/_build/build.js` 상단 `CHROME` 후보 목록에 경로를 추가합니다.

## 2. 파일 위치 규칙
| 문서 종류 | 위치 | 예 |
|---|---|---|
| 기획 (PRD) | `docs/PRD/NN_PhaseN_이름.md` | `02_Phase2_Sequencer_Core.md` |
| 설계 · 계획 · 매뉴얼 | `docs/이름.md` | `DB.md`, `Implementation_Plan.md`, `Git_Manual.md` |
| AI가 구현한 코드 설명 | `docs/ai-notes/NN_이름.md` | `01_dev_environment.md` |
| DB 스크립트 문서 | `studionx/db/docs/` (md + docx) | `StudioNx_DB_Guide.md` |
| PDF | md와 **같은 폴더, 같은 이름** `.pdf` | `Git_Manual.pdf` |

- 파일 이름: 영문, 단어는 `_`로 연결, 문서 제목은 한국어.

## 3. 공통 템플릿 (모든 문서)
```
# Studio Nx — <문서 제목>

| 항목 | 내용 |
|---|---|
| 기준 문서 | [00_PRD_Overview.md](PRD/00_PRD_Overview.md) 등 상대 링크 |
| 작성일 | YYYY-MM-DD |
| (선택) 대상 / 목적 / 상태 | ... |

---

## 1. <첫 섹션>
...
## 2. <두 번째 섹션>
### 2.1 <하위 섹션>
```

### 3.1 작성 규칙
| 규칙 | 내용 |
|---|---|
| 제목 | `# Studio Nx — 문서명` 한 번만. 섹션은 `## 1.`, `### 1.1` 처럼 **번호를 붙임** |
| 메타 표 | 제목 바로 아래 `항목 / 내용` 2열 표, 그 다음 `---` |
| 문체 | 한국어 존댓말(`~합니다`), **짧고 명확하게**. 한 문장에 한 가지 |
| 표 우선 | 나열·비교·요구사항은 문단보다 **표**로 |
| 강조 | 핵심만 `**굵게**`. 코드·파일·테이블·컬럼 이름은 `` `백틱` `` |
| 메모 | 보충 설명·주의는 `>` 인용문 |
| 링크 | 다른 문서는 **상대 경로** 링크, 위치는 `§3.2`처럼 섹션 번호로 |
| 그림 | 화면 배치는 코드 블록 안 **ASCII 박스 그림**(`┌ ─ ┐ │ └ ┘ ▶ →`) |
| 일정 | `mermaid` `gantt` 코드 블록 (PDF에서 자동으로 가로 페이지) |
| ERD | mermaid 쓰지 않음(선이 곡선). `docs/_build/erd.js` 수정 → `ERD.png` 생성 후 `![…](ERD.png)` |
| 상태 표시 | 결정 표에서 `✅ 적용` / `⏸ 보류` / `**결정 필요**` |
| 변경 이력 | 계속 바뀌는 문서(DB.md 등)는 끝에 `## N. 변경 이력` 표(날짜 / 내용) |
| 금지 | HTML 태그, 각주, 이모지 남발, 장문 문단 |

### 3.2 표 쓰는 법
- 첫 열은 짧은 키(ID, 이름), 마지막 열은 설명·비고.
- 요구사항 우선순위는 `필수` / `권장` / `추후` 세 가지만.
- 표 안 줄바꿈 금지 — 길면 문장을 나누거나 열을 추가.

## 4. 문서 종류별 템플릿
### 4.1 PRD (`docs/PRD/NN_*.md`)
메타 표: `기획서 기능 / 선행 Phase / 관련 페이지 / 전체 개요 / 구현 단계`. 섹션은 **항상 이 10개, 이 순서**:

| # | 섹션 | 내용 |
|---|---|---|
| 1 | 목표 / 배경 | 왜 필요한지 2~3줄 |
| 2 | 범위 | `### In scope` / `### Out of scope` 목록 |
| 3 | 사용자 스토리 | 표: `ID / 사용자 스토리` — `US-<Phase><NN>` (예: US-201) |
| 4 | 기능 요구사항 | `### 4.N 소제목`별 표: `ID / 요구사항 / 우선순위` — `FR-<Phase><NN>` |
| 5 | 비기능 요구사항 | 표: `구분 / 요구사항` |
| 6 | 화면 구성 | ASCII 화면 그림 + 설명 목록 |
| 7 | API 초안 | 표: `Method / Path / 설명` (FastAPI, `/api/v1` 생략) |
| 8 | 사용 테이블 | `[DB.md](../DB.md) §N 참고` + 테이블 목록 (컬럼은 반복하지 않음) |
| 9 | AI 역할 구분 | 표: `영역 / 이 Phase에서 AI가 하는 일` (HTML·CSS 작성, JS·백엔드 템플릿만, C++ 안 함) |
| 10 | 완료 기준 | `- [ ]` 체크리스트, 확인 가능한 문장으로 |

- ID가 기존 번호와 겹치면 `FR-21NN`처럼 4자리로 확장 (예: PRD 02의 FR-2101~).

### 4.2 매뉴얼 (`Git_Manual.md` 형식)
`1. 구조(그림 + 표) → 2. 기본 흐름(명령 코드 블록) → 3. 규칙 표 → 4. 자주 쓰는 명령 표 → 5. 실수했을 때 표 → 6. 하지 말 것 목록 → 7. 관리(설정) 표`

### 4.3 결정·제안 문서 (`Ai_feedback*.md` 형식)
맨 앞에 `## 0. 결정 현황` 표(`번호 / 제안 / 결정 / 반영 위치`) → 항목별 `### 번호 제목` + `- **내용**: / **이유**: / **DB 영향**: / **난이도**:` → 마지막에 반영 위치 정리 표.

### 4.4 AI 구현 설명 (`docs/ai-notes/NN_*.md`)
`1. 무엇을 만들었나(파일 / 역할 / 비고 표) → 2. 왜 이렇게 했나 → 3. 검증 결과 표 → 4. 남은 일(사용자) → 5. 자주 받을 질문 대비(Q/A)`.
기획서 규칙상 **AI가 구현한 코드는 반드시 이 문서를 남깁니다.**

## 5. PDF 만들기
### 5.1 새 문서를 빌드 목록에 추가
`docs/_build/build.js`의 `PDFS` 배열에 한 줄 추가:
```
{ out: 'New_Doc.pdf', title: 'Studio Nx', subtitle: '부제목', files: ['New_Doc.md'] },
```
- 여러 md를 한 PDF로 묶으려면 `files`에 순서대로 나열 (표지 → 목차 → 문서별 새 페이지).

### 5.2 실행
| 목적 | 명령 (저장소 루트에서) |
|---|---|
| 특정 PDF만 | `node docs/_build/build.js pdf New_Doc` (이름 일부 일치) |
| 모든 PDF | `node docs/_build/build.js pdf` |
| ERD.png만 | `node docs/_build/build.js erd` |
| 전부 | `node docs/_build/build.js` |

- **바꾼 문서의 PDF만** 다시 만드세요. 모두 다시 만들면 내용이 같아도 PDF 파일이 바뀌어 불필요한 커밋이 생깁니다.
- PDF가 뷰어에서 열려 있으면 덮어쓰기에 실패합니다(오류 없이 이전 파일 유지). 파일 수정 시각으로 갱신 여부를 확인하세요.

### 5.3 PDF 디자인 (build.js `CSS` — 바꾸지 말 것)
| 요소 | 값 |
|---|---|
| 용지 | A4 세로, 여백 16mm × 14mm. ERD·간트는 A4 가로(여백 8mm) 자동 |
| 글꼴 | 본문 맑은 고딕 10pt / 코드 Consolas 8.5pt |
| 색 | 제목 `#2a2280`, 강조선 `#4b3fd6`, 표 머리 `#eeecff`, 인용 배경 `#f8f7ff` |
| 구성 | 표지(제목·부제·날짜) → 목차(md 2개 이상일 때) → 문서마다 새 페이지 |

### 5.4 ERD 갱신
1. `docs/DB.md` 수정
2. `docs/_build/erd.js`의 `groups`(영역별 테이블·PK/FK/UQ 컬럼)와 `relations`(`[부모, 자식, 'N' | 'N?' | '1']`) 수정 — 요청자·작성자 FK는 선 없이 `'col → users'`로 표기
3. `node docs/_build/build.js erd` → `docs/ERD.png` (직각 직선, 2배 해상도)
4. `docs/ERD.md` 관계 표 갱신, 필요하면 `studionx/db/docs/ERD.png`에도 복사

## 6. Word(docx) 만들기 (DB 가이드 방식)
- 변환기: `studionx/db/docs/_build/md2docx.js` (A4, 맑은 고딕, 표 열 너비 자동, ERD 구간 가로 페이지, 번호 목록 자동 재시작)
- 실행: `cd studionx/db/docs/_build` → `npm install`(최초 1회) → `node md2docx.js`
- 다른 md에 쓰려면 스크립트의 입력·출력 파일 이름만 바꿉니다. 지원 문법: 제목(#~###), 표, 코드 블록, 번호/글머리 목록, `**굵게**`, `` `코드` ``, 이미지 한 줄.

## 7. 완료 전 검증 (필수)
| 확인 | 방법 |
|---|---|
| PDF 생성됨 | 파일 수정 시각이 방금인지 |
| 코드가 그대로 노출되지 않음 | PDF 텍스트에 코드 펜스(백틱 3개)나 `dateFormat`이 없어야 함 (`pypdf`로 추출해 검사) |
| 가로 페이지 | ERD·간트가 있는 문서는 해당 페이지가 가로인지 |
| 눈으로 확인 | 페이지 1~2장을 이미지로 렌더링해 표·그림 깨짐 확인 |
| 링크 | md의 상대 링크 경로가 실제 파일과 맞는지 |
| 용어 일관성 | 캐릭터·도우미 이름은 **Nyxi**, 테이블·컬럼 이름은 DB.md와 동일 |
