## 3. 이번에 확인한 것: 일러스트가 안 보이던 원인
사용자가 "에러 페이지와 `home.html`의 Development 일러스트가 안 보인다"고 알려 왔고, **코드 문제가 아니라 8000 포트에 백엔드 대신 정적 파일 서버가 떠 있었던 것**이 원인입니다.
- 당시 8000에는 `python -m http.server 8000 --bind 127.0.0.1`(제가 검증할 때 켜 둔 것)이 떠 있었습니다. 응답 헤더가 `SimpleHTTP/0.6 Python/3.14.7`이고 `/`가 디렉터리 목록이었습니다.
- 그 서버에서는 ①없는 주소가 http.server의 기본 404로 나와 **커스텀 오류 페이지(일러스트 포함)가 뜨지 않고**, ②`/api/v1/dev-notes`가 없어(404) `home.js`의 `loadDevNotes`가 실패 분기로 가서 Development 칸이 **'실패' 상태가 되어 일러스트를 숨깁니다**(문구만 남음. 설계대로입니다).
- 조치: 정적 서버를 끄고 진짜 백엔드(uvicorn)를 :8000에 띄웠습니다. 이후 헤드리스로 확인한 결과, `/does-not-exist`는 커스텀 404에 `error.png`가 587x648로 표시되고(naturalWidth 1408, 로드 완료), `/home.html`의 Development는 공지 0건이라 **'비어 있음' 상태가 되어 `idk.png`가 416x416으로 표시**됩니다.
- 교훈: 화면을 볼 때는 반드시 **FastAPI 백엔드(uvicorn)**:8000으로 봅니다. 정적 서버로는 Development 일러스트와 커스텀 오류 페이지가 나오지 않습니다.

## 5. 작업 규칙 (2026-10-17 기준으로 바뀐 것 포함)
- **JS와 백엔드는 작업 단위(예: S1-07 화면)마다 함수를 전부 이어서 구현**하고 함수마다 멈추지 않습니다. 함수 1개당 설명 문서(md+PDF)는 그대로 남깁니다. 작업 단위가 끝나면 함수 문서 **합본 PDF**와 작업 전체를 정리한 **개요 ai-note**를 만들고, **사용자 검토는 작업 단위가 끝난 뒤 한 번에** 받습니다(2026-10-17 변경, 이전에는 함수 하나씩 멈췄습니다).
- **화면 스크린샷 저장 위치(2026-10-17)**: AI가 확인·검토용이나 사용자에게 보여 줄 목적으로 찍는 스크린샷은 처음부터 `docs/screenshots/YYYY-MM-DD_주제/`에 저장합니다(임시 폴더에 두었다가 나중에 옮기지 않습니다). 디자인 목업은 `docs/page_mockups/<화면>/`.
- JS 실제 코드는 전통 문법(`?.`, `??`, `??=`, `||=`, `&&=` 금지). 최신 문법은 문서에만 적습니다.
- HTML/CSS는 AI가 쓰되 먼저 `studionx/frontend-reference/`를 봅니다. C++(`studionx/native/`)는 손대지 않습니다.
- 커밋·푸시는 사용자가 요청할 때만 합니다. PR은 `develop` 대상으로 만들고 병합은 사용자가 요청할 때 합니다. 병합 뒤에는 YouTrack 해당 이슈를 Closed로 하고 다음 작업을 요약합니다. 브랜치·커밋 규칙은 `docs/Git_Manual.md`를 봅니다.
- 줄 번호로 `sed`를 돌려 고치지 않습니다(내용으로 찾아 바꾸는 파이썬을 씁니다). 한글이 들어간 파이썬은 코드 페이지 때문에 깨질 수 있으니 파일로 쓴 뒤 실행합니다.
- 문서는 `docs/AI_Doc_Template_Guide.md`를 먼저 읽고 씁니다. 한국어 ~합니다체, 조사·어미를 살린 완성된 문장, "·"로 잇지 않고 쉼표와 조사를 쓰며, 산문에서 엠대시(—)는 쓰지 않습니다(H1의 "NN — 제목" 형식만 유지). PDF는 고친 문서의 것만 다시 만듭니다.
- PowerShell을 씁니다(`&&` 미지원, `cmd1; if ($?) { cmd2 }`). 한글 콘솔은 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`과 `$env:PYTHONIOENCODING="utf-8"`로 맞춥니다.
